
# Non-Functional Requirements

Non-functional requirements describe the quality, performance and security expectations of CampusConnect.

1. Security: User passwords must be securely stored.
2. Performance: Common pages should load within 3 seconds under the agreed test conditions.
3. Usability: The interface should be simple and user-friendly.
4. Reliability: The system should handle errors without losing confirmed submissions.
5. Compatibility: The application should support major modern browsers.
6. Maintainability: The code should be organised and easy to update.
7. Accessibility: The application should support keyboard navigation and readable contrast.
