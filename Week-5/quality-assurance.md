# Quality Assurance Plan

## 1. Introduction

Quality Assurance (QA) is the process of ensuring that software meets defined quality standards. For CampusConnect, QA will help identify problems early and improve the reliability, security, and usability of the application.

## 2. Quality Assurance Activities

- Review requirements before development.
- Follow consistent coding standards.
- Prepare test cases for important features.
- Perform unit, integration, and system testing.
- Check application security and performance.
- Record and resolve identified defects.
- Perform regression testing after changes.

## 3. Defect Management Process

The proposed defect management process includes:

1. **Identification:** Find an issue during testing.
2. **Recording:** Create a report with steps to reproduce it.
3. **Classification:** Assign severity and priority.
4. **Assignment:** Assign the issue to the responsible developer.
5. **Resolution:** Correct the identified problem.
6. **Retesting:** Verify that the correction works.
7. **Closure:** Close the issue after successful verification.

## 4. Defect Severity and Priority

| Level | Description |
|---|---|
| Critical | Major failure that prevents essential application usage |
| High | Important functionality is not working correctly |
| Medium | A feature has a problem but the application remains usable |
| Low | Minor interface or cosmetic issue |

## 5. Continuous Quality Improvement

The project team will review testing results, user feedback, and recurring defects. Lessons learned from each testing cycle will be used to improve future development and testing activities.

## 6. Conclusion

A planned QA process helps maintain software quality throughout the development lifecycle. Applying these activities will support the development of a reliable and user-friendly CampusConnect application.
